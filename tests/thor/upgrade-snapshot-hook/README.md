# Thor outgoing certificate snapshot entrypoint

The ipq807x platform omitted the pre-upgrade bank-local certificate export already present on ipq60xx. Its actual RAM writer consequently refused a missing snapshot before environment or bank writes. Both outgoing Thor03.1 and published07 have the same platform, exporter, writer and BusyBox hashes. A corrected target image cannot repair the outgoing image that must install it. The outgoing03.1 platform therefore requires a separately authorized bounded repair before retrying; no AP repair is executed by these tests.

Run `python3 test-entrypoint.py OLD_IMAGE_ROOT CANDIDATE_PLATFORM` on a build host with qemu-aarch64. The old root must contain the actual published BusyBox, certificate helper and writer. Tests use synthetic temporary files and boot/UBI metadata. Hardware identity/image predicates are isolated; the actual writer stops at its first environment-write boundary. Tests cover missing snapshots, real export and validation, pre-pivot export failure, non-Cambium behavior and both complete entrypoint paths. No firmware build, AP, mount, real ENV or flash operation occurs. New images must also prove their actual packaged platform equals the reviewed candidate.
