# Shared DFS readiness LED

The shared state daemon checks fresh `dfs_cac.collect()` evidence every ten seconds in a separate process with a five-second overall timeout. Only a positive current CAC result on an enabled radio requests a readiness pulse. Expired, aborted, disabled, unavailable or malformed evidence returns to the normal controller indicator. A one-second expiry timer discards results older than fifteen seconds; slow probes cannot stall state, identify or fault timers.

Connected/disconnected colours retain existing qualified board mappings. During CAC, the selected normal colour uses a kernel timer: 1900 ms lit, 100 ms dark. The helper owns that timer explicitly and preserves its cadence on repeated updates, including restore requests. Global LED disable, boot/recovery/upgrade, identify/factory reset and critical fault indications take precedence. Gambit retains its existing green/amber pair; no blue channel or unsupported mapping is invented. Cloud-only boards retain their prior behaviour.

Run `python3 tests/dfs-led/run-tests.py REPO BUILT_ROOT HOST_UCODE` on the existing SDK host. The tests execute the actual ARM helper and state source with LED/service boundaries mocked, the real install recipes, the bounded collector wrapper, and existing ordinary/MLO CAC classifier tests. They perform no AP configuration, radio or network operations.

The Miami optical trial is a separate LED-only simulation. It changes no radio channel or controller connection and installs no persistent code. Original sources and LED state are backed up; one-second safety checks abort for new priority indications; traps and a watchdog restore ordinary controller colour. Blue and green trials are measured separately. Optical evidence proves cadence and restoration, not an actual on-air CAC event or all-family hardware acceptance. Other AP rollout follows the tested Miami result and a dependency preflight under the existing conditional approval. No firmware build is part of this trial.
