# Miami off-device failure capture

This covers two observed failure modes: Linux remains reachable with storage
read-only, and a later reset leaves U-Boot unable to read either bank. The
per-boot sysfs first-failure record alone cannot survive either reset or cold
power. Periodic controller health is not a synchronous failure-capture path.

The diagnostic kernel patch caches and emits the original complete record
before any optional feature transaction. BEGIN/END, boot-relative timestamp,
14 registers, four parsed/page-scope codeword groups and four DMA records make
missing/truncated UDP output detectable. Supplemental feature results are
marked separately; no reset, recovery, extra array read or retry is added.
Existing first-event ownership and normal NAND error returns are retained.
The cached record indicates whether feature collection completed.

The AP package starts a dedicated, static RAM executable with locked pages.
It checks only the cached sysfs record once a second and exports a complete cached record in one direct UDP datagram, bypassing the
userspace printk rate limiter. The receiver acknowledges only after fsync of
the exact raw datagram and containing directory. The exporter retries missing
receipts; unchanged records are marked delivered only after a receipt. Boot,
sequence and nonce identify retry duplicates. It also sends a heartbeat every
30 seconds. It never reads NAND pages. Normal
kernel console output (panic/watchdog included when emitted) goes directly to
netconsole independently of that userspace watcher. The real management VLAN
interface must be used; the bridge slave eth0 is rejected by netpoll.

The package is disabled by default. Configure `/etc/config/miami_capture` with
a receiver IP/MAC/UDP port, then enable the diagnostic service. This changes
only its owned netconsole target; it never changes network/radio configuration.
The receiver is deliberately a LAN service, not a public unauthenticated log
endpoint. Pin and verify the real sender and receiver addresses at deployment.
Both receiver and network must remain available. Loss of heartbeats is a
monitoring gap, never a healthy interval. A host power loss, hard CPU halt
before printk, or U-Boot itself cannot be diagnosed by Linux netconsole;
continuous serial capture is needed for those cases.

`receiver.py` stores every accepted datagram with UTC receive time, sender,
SHA256 and exact base64 bytes, fsyncing each record before counting it saved.
Its atomic status distinguishes process liveness from a fresh AP heartbeat.
The receiver must run independently of this chat and survive a chat ending;
on macOS an owned LaunchAgent and its child-scoped idle-sleep assertion are
used. Do not claim continuity while that host is shut down or disconnected.

Validation:

* Run `tests/miami-nand/test-diagnostic.py --driver PREPARED_NEW_DRIVER`.
  It executes the actual parser/publisher and verifies that the full raw frame
  and cache exist even when a simulated feature callback never returns.
* Run against the actual deployed old driver with `--expect-old-failure`;
  it must fail specifically at `RAW_CACHE_BEFORE_FEATURE`.
* On a Linux build host, compile `monitor.c` with the host compiler and run
  `tests/miami-nand/test-exporter.py /absolute/path/to/monitor`: lost packet,
  lost receipt, and total receipt loss exercise the actual C sender.
* Run `tests/miami-nand/test-receiver.py`: binary-byte preservation, durable
  receipt, initial missing heartbeat, stale-gap status and clean shutdown.
* On hardware, use a synthetic record generated by the actual kernel formatter
  and `miami-capture-monitor --self-test /tmp/FIXTURE HEX_NONCE RECEIVER_IP RECEIVER_PORT`.
  The record envelope is marked synthetic and the real NAND buffer is not
  changed. Require the whole record, every field line and an exact byte comparison on
  the off-device disk, plus the durable-save receipt.
  This is a safe live transport test, not an intentional NAND failure or panic.

A fresh firmware must include the kernel ordering fix. A runtime netconsole
setup on an older kernel does not establish that the new publisher is running.
The live full-record test exposed 17 suppressed lines when exporting through
`/dev/kmsg`; that path must not be used for userspace snapshot bursts. Test
dropped datagrams, dropped receipts and complete receipt loss too: retry the
first two, and report failure for the last. The checksum in the receipt detects
accidental corruption; it does not authenticate a hostile LAN peer.

Retain the exact installed hashes, boot identity, receiver launch ownership,
raw live receipts and test limitations in private deployment evidence.
